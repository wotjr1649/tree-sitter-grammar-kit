The shared validator is the pure Go `src/kit/reuseobs` package, bounded by the [public API contract](../specs/public-go-api.md). Existing prohibitions on process, network, and internal execution packages in the offline closure remain intact. Opt-in batches save each validated frame's raw response by case without accumulating all responses. A failed write cannot leave execution marked successful.

This opt-in feature is under development. It does not establish a new main support verdict or a completed release. The owning contracts are the [native protocol](../specs/tree-and-adapter-protocol.md), [CLI](../specs/cli-and-profile.md), [replay/qualification](../specs/identity-and-evidence.md), and [validation](../validation/validation.md).

The existing public `TSNode.id` intersection counts reused public node identities. Public logger accept/reject events are a separate observation. With the pinned JSON grammar, `repair-close`, `break-close`, and `repair-colon` retained their BLOCKED public route verdicts while a local Windows check observed 1, 1, and 5 logger accept events. The controls that omitted the old tree observed zero accept events and failed the separate observation claim. The full comparison of all twelve public incremental/fresh CST fields remained in place. Event counts are not unique node counts, reuse ratios, or speed improvement percentages.

Only `incremental --reuse-observation` selects native r3 and result r2. The default native r1, existing result r1, and oracle r2 remain separate. The driver installs and restores public `TSLogger` for each call without adding a runtime source patch. Observations bind the pinned runtime manifest, verified build, run ID, case ID, history start, parse role, and current/previous input hashes. A restarted SVC segment retains local step zero while its history start prevents exchanging observations with another segment over identical input.

Completed zero counts are distinct from missing loggers, unexecuted parses, unknown formats, partial collection, cap stops, and synthetic overflow. Unknown keys, empty symbol payloads, events after completion, null strings, omitted counters or roles, and impossible byte prefixes cannot support successful observations. The overflow control injects counter state to test the defensive path. Normal bounded collection reaches the event cap before a 64-bit counter can overflow.

Offline `native-result-r3` rechecks observations and raw/projection agreement. An explicitly registered original-source witness allows input versions and edit points to be recomputed; hashes alone leave edit points UNRESOLVED. The CLI does not automatically copy source text. Current query/API qualification does not consume these observations and explicitly rejects records containing them. Successful logger collection does not promote existing route, language expectation, case assessment, or 78-cell support verdicts.

Local targeted checks cover normal/omitted old trees, missing loggers and formats, event order, three caps, synthetic overflow, missing host roles, batch isolation, SVC boundaries, the three JSON cases, CLI-to-replay, source witnesses and joint point mutations, and rejection of unsupported qualification traces.
