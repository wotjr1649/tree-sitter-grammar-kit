## API, CLI and schema consumption

The historical candidate comparison found no removals, 21 additions and nine changed declarations. API, CLI and schema changes for the new final candidate require fresh checks under #220. Changes include eight added fields across seven experimental structs and r1→r2 changes to SvcFormat/SvcCompositeSchema. Added fields can affect source compatibility for unkeyed struct literals. No existing field type or JSON tag was removed/changed in those seven structs. This is not a complete behavioral or wire-compatibility guarantee.

DeriveDynamicSQLChecked returns a typed error for invalid capture ranges. For such input, the existing DeriveDynamicSQL returns a zero value with empty Mapping rather than a valid empty fact result. ValidateTree rejects a root field and an empty field. SVC r2 and legacy r1 consumption boundaries must be pinned explicitly. [Public API contract](https://github.com/wotjr1649/tree-sitter-grammar-kit/blob/33f84fc32e0b6c92a2e41a5bdf11597f88c43ad8/docs/specs/public-go-api.md)

The current baseline is owned by [go.mod](../../go.mod), and these historical checks do not validate the new final candidate. That evidence is bound to `1e127a8` and is not inherited by the next documentation or final release candidate.
